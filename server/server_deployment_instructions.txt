SERVER DEPLOYMENT NOTES

These notes describe a generic deployment. They intentionally contain no real server address, account identifier, or secret path.

1. Provision a dedicated service account on <SERVER_HOST>.
2. Copy or clone the repository into <PROJECT_PATH>.
3. Create an isolated Python 3.10+ environment.
4. Install the root requirements and server/requirements.txt.
5. Store credentials in a protected secret store or files readable only by the service account.
6. Configure exchange IP allowlists when supported.
7. Keep withdrawal permission disabled unless the reviewed rebalancing workflow requires it.
8. Run public-data and demo validation before loading live credentials.
9. Run the live read-only suite and inspect all failures.
10. Start live mode only after reviewing docs/OPERATIONS.md and the exact configuration deployed.

Example:
  ssh <SSH_USER>@<SERVER_HOST>
  cd <PROJECT_PATH>
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  pip install -r server/requirements.txt
  python -m tracker
  python -m test_demo.run_all --skip-orders
  python -m test_live.run_all

The live entry point is:
  python main.py --live

Live mode may transfer balances, submit orders, incur fees, and create market exposure. It requires an explicit confirmation after preflight checks.

Operational logs and configuration snapshots may contain sensitive details. Keep them outside version control and restrict access.
